
## 일일 인기 상품 랭킹 집계 Redis 기반 설계 및 구현

### 배경 및 목표

이 기능은 실시간성과 성능을 보장하는 것으로, RDB 중심의 접근 방식은 집계 쿼리의 비용, 응답 시간, DB 부하 측면에서 한계가 명확했다.
이에 따라, Redis의 Sorted Set 자료구조를 활용하여 주문 완료 시점에 상품별 결제 수량을 누적하고, 사용자 요청 시 빠르게 일일 인기 상품 순위를 응답할 수 있도록 구조를 설계하였다.
이와 함께, 매일 자정마다 감쇠 연산을 적용하여 일일 트렌드를 반영할 수 있도록 구현하였다.

### Redis Sorted Set 기반 랭킹 설계

#### 로직 흐름

1. 결제 트랜잭션 성공 시, 각 결제 상품의 수량만큼 `ZINCRBY` 수행
2. 상품 ID를 member로, 수량을 score로 누적 기록
3. 매일 자정(`@Scheduled`) 감쇠 작업 수행

    * `ZSCAN` 으로 전체 멤버 순회
    * 각 score에 대해 `score * 0.5`
    * 감쇠 후 score < 1 이면 삭제
   
### 장점

* 실시간 데이터 반영
  - 결제가 완료되는 즉시 해당 상품의 수량이 랭킹에 반영되어 사용자에게 실시간 인기 정보를 제공할 수 있다.

- 경량화된 조회 성능
  - Redis의 Sorted Set은 O(logN) 수준의 삽입 및 정렬 성능을 제공하며, 상위 랭킹 조회도 ZRANGE를 통해 빠르게 처리할 수 있다.

- 단기 트렌드 중심 구조
  - 매일 자정마다 감쇠 로직을 적용함으로써 단기간에 인기를 끄는 상품이 자연스럽게 상위에 노출되고, 이전 데이터는 점진적으로 영향력을 잃도록 설계되어 있다.

- 비동기 갱신 처리
  - 결제 트랜잭션 내에서 직접 랭킹을 갱신하지 않고, 트랜잭션 커밋 이후 이벤트 리스너를 통해 Redis에 적재함으로써 트랜잭션 지연이나 병목을 방지하고, 시스템 전체 응답 속도를 개선하였다.


### 회고 및 보완점
해당 구조는 높은 성능과 실시간성을 바탕으로 빠른 응답을 제공할 수 있다는 장점이 있었지만, 운영 및 확장 측면에서 고려할 지점도 존재했다.

- 감쇠 로직 최적화 필요
  - 현재는 ZSCAN을 통해 score를 감쇠하고 조건에 따라 삭제를 반복 처리하고 있으나, 이는 반복 I/O로 인해 성능 이슈가 생길 수 있다.
  Lua Script를 사용하여 원자적이고 일괄적인 감쇠 처리를 도입하면 성능 개선이 가능하다.

- 기간별 랭킹 분리
  - 현재는 하나의 키(sorted-set:daily-popular-products)로 일별 데이터를 관리하고 있으나, 추후 주간 또는 월간 랭킹 데이터를 분리 저장하여 다양한 관점에서 인기도를 분석하고 제공할 수 있도록 확장할 필요가 있다.

- 데이터 정합성 고려
  - Redis는 인메모리 기반이기 때문에 장애 발생 시 데이터 유실 가능성이 존재한다. 이를 보완하기 위해 주기적인 백업, 또는 주기적으로 RDB에 동기화하는 구조도 함께 고민할 필요가 있다.
