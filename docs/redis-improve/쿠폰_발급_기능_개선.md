## 선착순 쿠폰 발급 Redis 기반 설계 및 구현

### 배경 및 문제 인식

기존의 선착순 쿠폰 발급 시스템은 RDB를 기반으로 설계되어 있어 사용자 요청마다 DB에 접근해야 했고,  
동시성 제어를 위해 분산락(Redisson Lock)을 사용했다.  
이러한 구조는 락 획득 및 해제 과정에서의 병목이 존재하며, 데이터베이스 부하와 트랜잭션 지연으로 인해 사용자 응답 속도가 늦어지는 문제가 있었다.  
이벤트 트래픽이 몰릴 경우 실제 사용자에게 발급 여부를 반환하기까지 많은 시간이 걸리며, 시스템 안정성까지 해칠 수 있는 구조였다.

### Redis 기반 재설계 목표

* **빠른 응답 속도 확보**
* **DB 트랜잭션 최소화**
* **중복 요청 방지**
* **재고 초과 방지**

### Redis 자료구조를 활용한 설계

Redis의 고속성과 원자적 명령의 특징을 활용하여 다음과 같은 구조로 재설계하였다.

#### 발급 로직

1. `GET coupon:amount:{couponId}`: 재고 확인. 존재하지 않으면 종료
2. `SADD coupon-issue-requesting-users:{couponId} {userId}`: 중복 요청 차단. 결과값이 0이면 중복 요청
3. `DECR coupon:amount:{couponId}`: 재고 차감. 결과값이 0보다 작으면 `DEL`로 키 제거 후 종료
4. `RPUSH coupon:queue:{couponId} {userId}`: 발급 대상 유저 큐 적재
    - 백그라운드 스케줄링으로 1초마다 `LPOP` → RDB 저장  
5. 성공 응답

### 장점 및 효과

* **응답 속도**: 전 과정이 Redis에서 처리되므로 사용자 요청에 대한 응답 속도 개선
* **분산 락 제거**: 원자 연산을 통한 동시성 제어 및 순서 보장 불필요로 분산락 제거
* **중복 방지**: 사용자 중복 요청은 `SADD`로 제어
* **초과 방지**: `DECR`로 정확한 재고 제어 가능
* **RDB 트랜잭션 최소화**: 중복발급의 경우 RDB를 통해 조회 했지만 redis 도입으로 트랜잭션 감소

### 회고 및 개선 가능성
해당 기능은 Redis 장애 시 쿠폰 발급 자체가 불가능해질 수 있으므로, Redis HA(High Availability) 구성이 필수적이다.
또한, 쿠폰 발급부터 대상 사용자의 RDB 적재까지의 과정을 기존의 스케줄링 방식이 아닌 이벤트 기반 구조로 전환할 경우,
실시간성 향상, 리소스 최적화, 병렬 처리 효율성 등 다양한 성능적 이점을 기대할 수 있다는 점에서 구조 개선이 필요할 수 있다고 생각하였다.
