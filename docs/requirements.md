# 📄 요구사항 정의서 - ecommerce 시스템

---

## ✅ 기능 요구사항
---

### 1️⃣ 잔액 충전 / 조회 API (`주요`)

- **목적**: 사용자의 충전 잔액을 관리하고 확인할 수 있도록 함
- **조건**
  - 충전 금액은 1원 이상



---

### 2️⃣ 상품 조회 API (`기본`)

- **목적**: 상품 목록 및 잔여 수량 확인
- **조건**
  - 조회 시점 기준의 최신 재고 수량 제공
  - 품절된 상품도 목록에 포함 가능
  - 상품 옵션 별 재고 조회 가능

---

### 3️⃣ 선착순 쿠폰 기능 (`주요`)

- **기능**
  - **쿠폰 발급 API**: 선착순 조건으로 사용자에게 쿠폰 발급
  - **보유 쿠폰 조회 API**: 사용자가 가진 쿠폰 목록 반환
- **조건**
  - 발급 수량 제한 존재 (선착순)
  - 주문 시 쿠폰을 적용해 전체 금액 할인
  - 한명의 사용자가 동일한 쿠폰을 중복 발급 받을 수 없음

---

### 4️⃣ 주문 / 결제 API (`주요`)

- **목적**: 상품 주문 및 잔액 기반 결제 처리
- **조건**
  - 주문 정보는 외부 데이터 플랫폼으로 전송 (mock/fake 등으로 대체 가능)
  - 트랜잭션 원자성 보장
  - 쿠폰 사용은 주문당 한번 사용 가능

---

### 5️⃣ 상위 상품 조회 API (`기본`)

- **목적**: 최근 3일간 가장 많이 팔린 상위 5개 상품 조회
- **조건**
  - 결제 완료된 주문 기준
  - 최근 3일: 오늘을 제외한 직전 3일


---

## ✅ 비기능 요구사항

| 항목         | 설명                                                                 |
|--------------|----------------------------------------------------------------------|
| 동시성 제어         | 동시 쿠폰 발급, 주문 처, 포인트 충전/차감 등에서 race condition 방지                ||
| 테스트       | 단위 및 통합 테스트 작성 |
| 확장성       | Redis, Kafka, 이벤트 시스템 연동을 고려한 구조 설계                   |
| 성능       | 일정 수준 이상의 트래픽에도 안정적으로 견딜 수 있는 성능을 확보해야 한다. (최적화된 DB 및 인프라 설계)|

---

## 📝 참고

- 외부 데이터 플랫폼 전송은 실제 연동 없이 mocking/fake 방식으로 처리 가능
- API 응답은 RESTful 원칙에 따라 설계
